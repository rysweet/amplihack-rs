Issue #1932 review correction and host handoff (2026-11-10)

Security-review correction
This intentionally extends the diagnostics-only scope: send_resume reuses
Deps::pane (SystemDeps calls keys::verify_pane) immediately before each key,
requiring the same pane selected before guard commit. Liveness and foreground
checks, Escape/Ctrl-U/literal continue/Enter, shared swap judgment and durable
authorization are preserved. Failure reports resume-keys-failed with
PermissionDenied and the successful-key count, leaves the guard committed,
and never switches to exit two. Verification and tmux delivery are separate
operations; this narrows but cannot eliminate the final process/terminal race.

Regressions in limit_resume_decide.rs cover ownership loss after initial
selection and before each of the four keys, with no subsequent delivery,
no stderr/exit-two fallback, a retained commit and bounded failure diagnostics.

Logging-failure behavior
SystemDeps::{log,diagnostic} skip logging if ensure_resume_dir fails.
log::append returns without output if a private-directory/file check, lock,
metadata lookup or rotation fails; write_all errors are ignored. Partial
records are possible on write failure. There is no retry, fallback, or guard
mutation in this path. Therefore absent receipts do not prove absent hook
invocations. The continuation result still follows the authorization decision;
logging does not authorize it. The new refused_diagnostic_writes regression
calls the real append function against a file instead of a directory and checks
one authorized delivery, suppression of duplicate delivery, no exit-two
fallback, and no keys when guard commit fails. The existing
append_never_writes_through_a_symlink_and_never_panics regression covers
refused log targets. No logging defect was established; logging policy is
unchanged, including silence when diagnostics cannot be persisted.
